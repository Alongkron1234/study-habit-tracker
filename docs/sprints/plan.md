# แผน 3 Sprint (Part D)

**ผลิตภัณฑ์:** Study Habit Tracker | **อ้างอิง:** SRS v0.2, `features.md` v0.1, `traceability.md` v0.1 | **เวอร์ชัน:** 0.1 (ร่าง)

## 1. ภาพรวม

แผนแบ่ง feature ทั้ง 16 รายการ (F-01 ถึง F-16) ลง 3 sprint ให้ครอบคลุม baseline ทั้งหมด โดยผูกกับกำหนดส่งจริงของวิชา

| Sprint | ช่วงเวลา | เป้าหมาย | Checkpoint |
|---|---|---|---|
| 1 | ถึง 8 พ.ย. | ผลิตภัณฑ์เล็กที่ทำงานได้: auth + สิทธิ์ + ข้อมูลถาวร + domain slice | Deliverable 1 (8 พ.ย.) |
| 2 | 9–29 พ.ย. | ขยายแกนหลัก: แก้ไข/archive/แก้ entry ภายใต้ contract | Deliverable 2 (29 พ.ย.) ต้องเสร็จครบ |
| 3 | 9 พ.ย. – 13 ธ.ค. | feature ที่เหลือ, integration, hardening, แก้ defect | คืบหน้าที่ 29 พ.ย. เสร็จ 13 ธ.ค. |

หลักการ: feature ของ sprint ใดต้องมี contract (Feature SDS, AC, STS, DoD) ก่อน implement เสมอ และถ้าต้องย้าย feature ข้าม sprint จะบันทึกเป็นการเปลี่ยนที่มีเหตุผล ไม่ลดงานเงียบๆ

## 2. Sprint 1: ผลิตภัณฑ์เล็กที่ทำงานได้

**เป้าหมาย:** ผู้ใช้ login ได้ PM สร้างแม่แบบ Participant ตั้งเป้าหมาย บันทึกรายวัน และดูความคืบหน้า โดยมีเทสต์สำหรับกฎธุรกิจ สิทธิ์ และการเก็บข้อมูลถาวร

| Feature | ชื่อ | Requirement หลัก |
|---|---|---|
| F-07 | ข้อมูลถาวรและ seed | NFR-04 (และ unique constraint ของ NFR-05) |
| F-01 | การยืนยันตัวตน | FR-01–03, NFR-01–03 |
| F-02 | การควบคุมสิทธิ์และ error ปลอดภัย | BR-07, BR-08, NFR-06 |
| F-03 | แม่แบบกิจกรรม | FR-04–06, BR-02, BR-09 |
| F-04 | การตั้งเป้าหมาย | FR-07, BR-04, BR-05 |
| F-05 | บันทึกรายวัน | FR-08, BR-01–03, NFR-05 |
| F-06 | ความคืบหน้าและประวัติ | FR-09, FR-10, BR-06 |
| F-08 | ติดตั้งและ config | NFR-07, NFR-08 |

**Dependency:** F-07 → F-01 → F-02 → F-03 → F-04 → F-05 → F-06 และ F-08 ทำคู่ขนาน

**ผลลัพธ์ที่ถือว่าเสร็จ (completion outcome):**
- release บน `main` พร้อม tag ที่รันในเครื่องได้ตาม README
- journey: PM สร้างแม่แบบ → Participant ตั้งเป้า → บันทึกรายวัน → ดูความคืบหน้าและประวัติที่บันทึกไว้
- กรณีปฏิเสธตามกฎ (บันทึกซ้ำวันเดียวกัน) และกรณีต้องห้าม (PM อ่านข้อมูลของ Participant) พร้อมเทสต์
- เทสต์อัตโนมัติผ่านและเก็บผลผูกกับ commit; Issue/PR ที่เพื่อน review แล้ว

**ทำไม Sprint 1 ขนาดนี้ทำได้จริง:** เลือกกฎ 1 entry ต่อวันและหน่วยเดียว (นาที) ไม่มีการแก้ไขข้อมูลหลังบันทึก และทิ้งการสมัครสมาชิกไว้นอกขอบเขต ทำให้ domain slice มีแค่ 4 feature ต่อกัน ส่วน F-02, F-07, F-08 เป็นงานพื้นฐานขนาดเล็ก

**แผนรายวันของ Sprint 1** (ปรับได้):

| วันที่ | งาน |
|---|---|
| 2–3 พ.ย. | ยืนยัน SRS, ทำ Part B/D, ร่าง SDS, สร้าง repo และ board |
| 3–5 พ.ย. | Workshop, SDS ให้เสร็จ, contract ของ F-07/F-01/F-02/F-03 (commit แยกก่อนโค้ด) |

| 7 พ.ย. | integration test บน staging, release PR เข้า `main`, tag |
| 8 พ.ย. | เก็บหลักฐาน รวม PDF ส่ง |

| Feature | ชื่อ | Requirement หลัก |
|---|---|---|
| F-09 | แก้ไข/archive แม่แบบ | FR-11 |

**Dependency:** F-09 ต้องมี F-03/F-04, F-10 ต้องมี F-04/F-06, F-11 ต้องมี F-05, F-12 ต้องมี F-06

**ผลลัพธ์ที่ถือว่าเสร็จ:** ทุก feature ข้างต้นมี contract ก่อน implement, เทสต์ผ่าน, review และ integrate แล้ว, regression ของ Sprint 1 ยังผ่าน (โดยเฉพาะ BR-01/02/03 และ BR-08), deploy ผ่าน pipeline จาก Lab 5

**ข้อควรระวังเรื่องเวลา:** ช่วงนี้ตรงกับ Lab 5 (ส่ง 15 พ.ย.), Lab 6 (22 พ.ย.), Lab 7 (29 พ.ย.) จึงวางงาน Sprint 2 ให้เล็กและเสร็จเร็ว เพื่อเหลือแรงให้ lab ซึ่งใช้ผลิตภัณฑ์ตัวเดียวกัน หลักฐานของ lab ต้องแยกจาก feature ปกติให้ชัด

**เป้าหมาย:** เพิ่ม feature ที่เหลือ รวมทุกอย่าง ตรวจจับและแก้ defect ให้ผลิตภัณฑ์พร้อม release สุดท้าย

| Feature | ชื่อ | Requirement หลัก | เป้าหมายที่ 29 พ.ย. |
|---|---|---|---|
| F-13 | Streak | FR-14 | **implement และเทสต์แล้ว** (workflow Sprint 3 อย่างน้อย 1 อย่างที่ Deliverable 2 ต้องมี) |

| F-15 | ตารางเตือน | FR-16 | มี contract แล้ว |
| – | Hardening | – | รวม error handling, การใช้งานง่าย, regression, แก้ defect |

**Dependency:** F-13 ต้องมี F-05/F-11, F-14 ต้องมี F-06/F-13, F-15 ต้องมี F-04

**ผลลัพธ์ที่ถือว่าเสร็จ (13 ธ.ค.):** ทุก requirement ใน SRS มีสถานะและหลักฐานการตรวจสอบ, ผลิตภัณฑ์ที่ deploy แล้วผ่านเทสต์ regression, defect วิกฤตที่รับมาแล้วถูกแก้, รายงาน PDF + วิดีโอ demo

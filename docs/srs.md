## 1. ปัญหาของ stakeholder และบริบท

นักศึกษาที่อยากสร้างนิสัยการอ่านหนังสือสม่ำเสมอ ไม่มีเครื่องมือง่ายๆ สำหรับตั้งเป้าหมาย บันทึกสิ่งที่ทำจริงในแต่ละวัน และดูว่าคืบหน้าไปแค่ไหน ขณะเดียวกัน โปรแกรมหนึ่ง (เช่น ชมรมติวหรือกลุ่มที่ปรึกษาทางวิชาการ) ต้องการให้ **Program Manager** กำหนดแม่แบบกิจกรรมมาตรฐานชุดเล็กๆ และให้ **Participant** ใช้แม่แบบนั้นตั้งเป้าหมายและบันทึกผลแบบเป็นส่วนตัว

**บริบทที่เลือก:** นิสัยการเรียนรายวัน กิจกรรมที่ติดตามใน baseline คือ **การอ่านหนังสือ วัดเป็นนาทีต่อวัน**

ผลิตภัณฑ์นี้เป็น **ระบบบันทึก (recording system)** เก็บสิ่งที่ผู้ใช้รายงานและคำนวณความคืบหน้าเท่านั้น ไม่ให้คำแนะนำการเรียน และไม่ประเมินผลการเรียนของผู้ใช้

## 2. ผู้ใช้งานระบบ (Actors)

| Actor | หน้าที่ |
|---|---|
| **Program Manager (PM)** | สร้างและดูแลแม่แบบกิจกรรม (ชื่อ, หน่วย, ช่วงค่าที่ถูกต้อง) **ไม่สามารถ** เห็นเป้าหมายหรือบันทึกส่วนตัวของ Participant |
| **Participant** | เลือกแม่แบบ ตั้งเป้าหมายส่วนตัว บันทึกรายวัน ดูความคืบหน้าและประวัติของตัวเอง เห็นได้เฉพาะข้อมูลของตัวเอง |

หนึ่งบัญชีมีหนึ่งบทบาทเท่านั้น บัญชีสร้างจาก seed data

## 3. ขอบเขต (Scope)

**อยู่ในขอบเขต (ทั้งผลิตภัณฑ์ Sprint 1–3):**
- การยืนยันตัวตน (login, logout, ข้อมูลผู้ใช้ปัจจุบัน) และการควบคุมสิทธิ์ตามบทบาทที่ฝั่ง server
- แม่แบบกิจกรรมที่ PM ดูแล
- เป้าหมายส่วนตัวที่อิงแม่แบบ
- บันทึกกิจกรรมรายวันพร้อมการตรวจสอบความถูกต้อง
- การคำนวณความคืบหน้า และประวัติการบันทึก
- (Sprint ถัดไป) แก้ไขเป้าหมาย แก้ไขบันทึก streak สรุปผล และการเก็บตารางเตือน

**ขอบเขตของ Sprint 1:** ข้อกำหนดที่ระบุ Sprint 1 ในหัวข้อ 5 ทั้งหมด

## 4. สิ่งที่ไม่ทำ (Exclusions)

- คำแนะนำหรือการประเมินด้านสุขภาพ การเรียน หรือประสิทธิภาพของผู้ใช้
- สมัครสมาชิกเอง กู้รหัสผ่าน ยืนยันอีเมล การจัดการบัญชีขั้นสูง หลายบทบาทต่อบัญชี
- การให้ PM เข้าถึงเป้าหมายหรือบันทึกของ Participant รวมถึงการแชร์ข้อมูลแบบได้รับความยินยอม
- การส่งการแจ้งเตือนจริง (อีเมล push SMS) ทำเพียงเก็บและแสดงตารางเตือน
- ฟีเจอร์โซเชียล กระดานอันดับ กลุ่ม
- API ภายนอกและข้อมูลจริง (ใช้ข้อมูลสังเคราะห์ทั้งหมด)
- แอปมือถือเนทีฟ และหลายเขตเวลา (ทุกวันที่ใช้เวลา Asia/Bangkok)

## 6. กฎทางธุรกิจ (BR)

| ID | กฎ | ตรวจสอบด้วย |
|---|---|---|
| BR-01 | หนึ่ง goal มี **ได้ไม่เกิน 1 entry ต่อวันที่** การบันทึกซ้ำวันเดียวกันถูกปฏิเสธและไม่เก็บอะไรเพิ่ม (รวมถึงกรณีส่งพร้อมกัน) | Unit + API/DB integration |
| BR-02 | ค่าของ entry ต้องเป็นจำนวนเต็มอยู่ระหว่างค่าต่ำสุดและสูงสุดของแม่แบบ (ค่าต่ำสุดของแม่แบบต้อง ≥ 1 เพดานของแพลตฟอร์ม 960 นาทีต่อวัน) ค่านอกช่วงหรือไม่ใช่จำนวนเต็มถูกปฏิเสธ | Unit (boundary: 0, 1, 960, 961, ทศนิยม) |
| BR-03 | วันที่ของ entry ต้องอยู่ระหว่างวันเริ่มและวันสิ้นสุดของเป้าหมาย **ไม่เป็นวันในอนาคต** และไม่ย้อนหลังเกิน **7 วัน** | Unit + API |
| BR-04 | เป้าหมายต้องมียอดรวมเป็นจำนวนเต็มบวก วันสิ้นสุดไม่ก่อนวันเริ่ม วันเริ่มต้องไม่ก่อนวันนี้ และระยะเวลาไม่เกิน 365 วัน | Unit + API |
| BR-05 | เป้าหมายมีสถานะ **active** ตั้งแต่สร้างจนถึงวันสิ้นสุด (รวมวันนั้น) หลังจากนั้นเป็น **ended** และรับ entry ใหม่ไม่ได้ Participant มีเป้าหมาย active ได้ **ไม่เกิน 1 เป้าหมายต่อแม่แบบ** | Unit + API |
| BR-06 | ความคืบหน้า (%) = (ผลรวมค่า entry ของเป้าหมาย) ÷ ยอดเป้าหมาย × 100 ปัดเป็นทศนิยม 1 ตำแหน่ง แสดงสูงสุด 100% แต่ยอดรวมจริงยังแสดงเต็ม | Unit |
| BR-07 | เฉพาะ PM เท่านั้นที่สร้าง แก้ไข หรือเก็บถาวรแม่แบบได้ Participant ทำไม่ได้ | API (role test) |
| BR-08 | Participant อ่านและเขียนได้เฉพาะเป้าหมายและ entry ของ **ตนเอง** PM อ่านเป้าหมายหรือ entry ของ Participant ใดๆ ไม่ได้ | API (ownership + role test) |
| BR-09 | หน่วยของแม่แบบคงที่ตลอดอายุแม่แบบ และ entry ใช้หน่วยของแม่แบบที่เป้าหมายอ้างอิง | Unit |

## 9. สมมติฐาน (Assumptions)

- A-01: ผู้ใช้เข้าระบบผ่านเว็บเบราว์เซอร์
- A-02: วันที่ใช้ปฏิทินตามเวลาเซิร์ฟเวอร์ Asia/Bangkok
- A-03: ใช้ข้อมูลสังเคราะห์เท่านั้น ไม่เชื่อมบริการภายนอก
